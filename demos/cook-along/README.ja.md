# Cook Along

[English](README.md) | [简体中文](README.zh-CN.md) | 日本語 · [Starter Kit](../../README.ja.md)

Rokid Glasses 向けのローカル手順ガイドとタイマーです。コーヒー、お茶、工作など、短い作業手順を案内する作品の出発点にできます。

[約30秒の診断用実演を見る（MP4）](media/demo.mp4)。修正した Ink 0.19.0 の実際の診断用ブラウザー画像を編集した動画です。連続したリアルタイム録画ではなく、Studio・眼鏡・実モデル接続のエビデンスでもありません。

修正した Ink 0.19.0 で実際に取得した Cook Along のブラウザー画像です。UI の診断用であり、AIUI Studio・物理眼鏡の検証ではありません。

| 基本情報 | このデモ |
| --- | --- |
| 対象 / UI | AIUI 0.19.0、英語の Page UI、`_current` と `_blank` |
| 主な流れ | レシピ選択 → 手順を進める → 待ち時間を計る → 完了または再開 |
| プリセット | `coffee`：Pour-over coffee、`pasta`：Tomato pasta |
| ネットワーク / キー / 権限 | アプリのネットワーク要求、外部 API、API キー、カメラ権限は不要 |
| ソースのインポートルート | Starter Kit ルートから `demos/cook-along/app` |
| 開発ツール | 外部の `rokid-aiui-agent` DevKit Skill |

「オフライン」は Page を開いた後のレシピ・タイマー機能を指します。ホスト起動、クラウド音声、インストールは含まず、別途実機確認が必要です。このデモは実行時に AI モデルを呼び出しません。

## 最短手順：インポート → 実行 → 変更

先に Starter Kit をクローンし、コーディングツールに [DevKit をインストールして読み込み](../../README.ja.md#1-devkit-をインストールして読み込む)ます。

1. **インポート：**AIUI Studio で `app.json` を直接含む `demos/cook-along/app` を選びます。下の GitHub 座標も使えます。
2. **実行：**`pages/index` を `_blank` で開き、**Pour-over coffee** → **Next step** → **Start timer** を選びます。API キーは不要です。
3. **変更：**下の依頼例 1 を使い、DevKit に `app/lib/recipes.js` の最初の手順を変更させます。**Starter Kit のルート**で検証し、編集した App を開き直すか再インポートして、文章の変化を確認します。

   ```bash
   npm ci --ignore-scripts --no-audit --no-fund
   npm test
   npm run verify
   ```

GitHub からは次の正確な座標でインポートします。記録済みのソースを再現する場合、`main` の代わりに対応する commit を指定してください。

```text
Repository: https://github.com/BreezeLife/rokid-aiui-starter-kit
Ref: main
Directory: demos/cook-along/app
```

## 動作と範囲

選択画面からレシピを開き、前後の手順へ移動します。時間を計る手順では開始、一時停止、再開、リセットができます。別の手順に移ると直前のタイマーは終了します。レシピを最初からやり直す、完了する、別のレシピを選ぶ操作もできます。

コーヒーは蒸らし30秒と抽出90秒、パスタはソース120秒と茹で時間480秒をプリセットにしています。実際のパスタの茹で時間は包装に従ってください。いずれも変更できるデモデータです。タイマー終了で自動的に次の手順へ進むことはありません。

タイマーは絶対終了時刻を基準にします。Page が非表示の間は表示更新を止め、再表示時に残り時間を計算します。Page を閉じるとセッションを破棄します。システムアラーム、音、バックグラウンドサービス、保存済みタイマーの復元はありません。ボタンはフォーカス・タップに対応し、ハードウェア入力は実機で確認する必要があります。

## 最初に変更する3か所

パスは `demos/cook-along/` からの相対パスです。まず次の**3か所**を変更します。

| 順序 | ファイル | 最初の変更 |
| --- | --- | --- |
| **1 · データ** | `app/lib/recipes.js` | レシピ名、手順、または `timerSeconds` |
| **2 · UI** | `app/pages/index.ink` | 画面の見出し、ボタン文言、手順のレイアウト |
| **3 · Agent のプロンプト** | `app/AGENTS.md` | 実行時 Agent の紹介と Page を開く指示。モデル API は不要 |

レシピ ID を追加するときは `app/pages/index.ink` の Page schema の列挙値と `app/AGENTS.md` の実行時指示も更新します。各手順を一目で読める量にしてください。App 情報は `app/app.json`、動作の回帰テストは `tests/` にあります。他のデモや自分の `app/` 外のファイルを App から参照しないでください。

## 短い実演手順

1. 選択画面を開き、**Pour-over coffee** を選びます。
2. 蒸らしの手順でタイマーを開始し、一時停止・再開します。残り時間を確認します。
3. 次の手順に進み、前のタイマーが止まることを確認します。完了まで進めて選択画面に戻ります。
4. オフライン確認では、開いた後に接続を切って主要操作を繰り返します。実際のデバイス・ホスト・結果を記録します。オフライン起動の検証とは別です。

計時中に Page を隠して戻る動作、終了して開き直す動作、両方の表示先も確認してください。短い実演ではプリセットの全時間を待つ必要はありません。完了状態の確認には制御可能な時計を使うテスト、またはテスト用と明記した短い時間設定を使います。

ブラウザーで限定的なレイアウト・クリック確認を行う場合は、[任意の診断用プレビュー手順](../../README.ja.md#任意のブラウザー診断用プレビュー)を参照してください。ツールが修正するのは `output/` 配下の別ランタイムで、その結果は標準プレビュー・Studio・実機の PASS ではありません。

## 検証状況

決定論的なローカルテストと AIUI 0.19.0 の厳格なソース検証は合格しました。ソースに結び付いた UX・機能項目は [verification/AUDIT.md](verification/AUDIT.md)、実行した検証とパッケージの結果は[ルートの検証レポート](../../verification/README.md)を参照してください。未修正の AIX ブラウザープレビューは App 読み込み前に失敗し、別途修正した診断用プレビューで UI が描画されても標準プレビューの PASS にはなりません。Studio と物理眼鏡は **BLOCKED** です。 ホストのオフライン起動も **BLOCKED** です。ローカル検証は Studio の受け入れや特定機種の動作確認を代替しません。
