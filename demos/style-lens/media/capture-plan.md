# Style Lens capture plan

A [30-second diagnostic screenshot walkthrough](demo.mp4) is now available; [media notes](README.md) describe its source and limits. It uses patched Ink 0.19 in a browser and is not Studio/device footage. The original Studio/device listing captures described below remain pending. Capture owner: hackathon organizer/device tester. Record the exact source fingerprint, runtime, glasses firmware, surface, timestamp and evidence layer when those captures are made.

1. **Sample Work image:** Import `../app` into Studio, open `pages/index/index` in `_blank`, keep configuration blank, record the SAMPLE and “Example: blue shirt” labels and all three tips. Confirm no camera prompt or network request occurs.
2. **Sample Evening image:** Focus the Evening button with the host's actual input and activate it. Record visible selected-occasion text and changed tips; retain evidence of focused/unfocused behavior.
3. **Live recovery image:** In a private configured copy, select Live, choose Capture & send and deny camera permission. Record actionable error with Use Sample / Retry. Also test unavailable backend separately; never stage a successful Live result.
4. **30–40-second video:** Show 0–5 s opening Sample, 5–12 s changing occasion, 12–18 s selecting Live with its data-transmission notice, 18–30 s actual camera capture and real advice only if the service/device check succeeds, 30–40 s return to Sample. If Live is unavailable, record Setup needed and Sample recovery instead and label the entire video Sample/setup. Do not replace network waits or results with fabricated UI.

Aim for three PNG/JPG stills plus one MP4. Official requirements specify 3–5 preview files with both image and video and a maximum video duration of 60 seconds. Square framing, a 15–45-second video and files up to 50 MB are recommendations, not additional hard platform limits. Check the current form for pixel and codec rules before export.

Do not expose provider credentials, temporary team tokens, personal faces, or private host URLs in recordings. Prefer photographing an owned garment against a neutral background. Preserve evidence originals where required; document crop, redaction and editing. Record bright, dark and cluttered optical backgrounds on physical glasses separately from listing media. Studio/preview frames do not count as physical-device evidence.

Owner: project maintainer / Hackathon organizer. Status: BLOCKED pending the required runtime, device, service configuration and actual captures. Upload and platform submission are not part of this preparation.
